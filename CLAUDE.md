### ⚠️ BRACE BALANCE ALONE IS NOT SUFFICIENT — `node --check` IS MANDATORY
Brace balance counts `{` against `}`. It is **blind to every error that does not change that
count**, and it has now passed a genuinely broken file **twice**:

| build | the defect | brace balance | `node --check` |
|---|---|---|---|
| **r84** | an unterminated string literal | **passed** | caught it |
| **r97** | a bash heredoc ate the `\n` escapes in the rollover `confirm`, putting **real newlines inside a string literal** | **passed** | caught it |

Both would have shipped a file that throws on load — and a render-time throw looks exactly
like a stale GitHub Pages cache, which is the single most expensive way to lose an afternoon.

**Run `node --check` on EVERY `<script>` block on EVERY build.** Extract the blocks to files
first; the checker must be given a real path, not a pipe:

```bash
python - <<'PY'
import re, io, os, subprocess
REPO = r'C:\Users\Sculp\Documents\auditpro'
OUT  = os.environ.get('TMP', '.')
ok = True
for f in ['index.html', 'mobile.html', 'mobile2.html']:
    c = io.open(os.path.join(REPO, f), encoding='utf-8').read()
    for i, x in enumerate(re.findall(r'<script[^>]*>(.*?)</script>', c, re.DOTALL)):
        p = os.path.join(OUT, 'chk_%s_%d.js' % (f.replace('.html',''), i))
        io.open(p, 'w', encoding='utf-8').write(x)
        r = subprocess.run(['node','--check',p], capture_output=True, text=True)
        print('%-13s block %d  %s' % (f, i, 'OK' if r.returncode==0 else 'FAIL\n'+r.stderr))
        ok &= r.returncode == 0
print('ALL VALID' if ok else 'BROKEN')
PY
```

**Windows trap that CAUSED the r97 case:** a bash heredoc — even a quoted `<<'PY'` one —
mangled `\n` escapes on the way into Python, so a JS `'\n\n'` reached the file as two literal
newlines. **Write multi-line edit scripts to a real `.py` file** (the `Write` tool) and run
that, instead of piping a heredoc, whenever the content contains backslash escapes.

## Standing rules — every build
Each exists because skipping it once shipped a defect or a false claim.

1. **`node --check` every `<script>` block, plus brace balance** (above).
2. **Verify every line number yourself.** Every `:NNNN` here and in a prompt drifts on every
   build. Re-grep by name and READ the code first; never change anything you have not read.
3. **Snapshot the pre-change file before the first edit**, so the old build can run beside the new.
4. **Dual-build gate for anything near the compute path.** Boot both builds in two node `vm`
   contexts and diff the REAL `computeVariances` + `calculateReportData` over live rows: every
   period twice (as stored, and forced `reopened`), a **fresh deep clone per run**, and the field
   list **auto-derived** from the union of keys (a hand-listed set missed `varMl` in r86). Plus the
   **structural** check: extract the CRITICAL compute functions from both builds with the
   mode-stack scanner and compare byte-for-byte — an identical body cannot produce a different
   number.
5. **Prove negative claims by derivation** — "writes nothing else" is a whole-object diff whose
   changed-key set is derived (r96); a side effect is measured, not assumed (r92). Always include a
   **negative control**: a banner that always renders proves nothing.
6. **A red test may be the harness's fault; a green one may be vacuous.** Run the check against
   the pre-change build before believing a failure (r88); confirm the fixture reaches the path
   (r97). Never loosen an assertion until it passes. Never let a fallback in a diagnostic decide a
   field name (r99: `d.lines`, not `d.items`).
7. **Report before committing.** Every build ends with a report — what changed, what was measured,
   what was deliberately left out. Commit and push only when the prompt says to. Docs-only changes
   say so in the subject and do not bump `APP_VERSION`.
8. **Multi-line edit scripts go in a real `.py` file**, never a heredoc or `sed`, when the content
   holds backslash escapes (the r97 trap).
9. **Harnesses live in the scratchpad, never the repo.** Venue-data backups are never committed
   (public repo). **Never print a key value** into a transcript, doc, commit or artifact.

## Audit Period Lifecycle

`c.auditSessions[]` is an ordered chain of **periods**. This is the core domain model — read
this section before touching variance, finalise, invoices, or anything period-shaped.

### Session shape
```javascript
{
  id, seq,                  // seq drives ordering (compareSessions: seq → openDate → id)
  prevId, nextId,           // explicit chain links (legacy chains may lack these)
  label, status,
  openDate, closeDate, periodDays,
  opening: {},              // deep copy of the PRIOR period's closing
  purchases: {},            // FROZEN resolved purchases once closed
  sales: {}, salesRows: [],
  closing: {},              // { productName: { qty, unit, … } } — countToUnits reads this
  varRows: [], overallVariancePct,
  amendments: [],           // audit trail of closing-count edits (r66)
  reclosedAt, _preReopen,
}
```

### Statuses
| Status | Meaning |
|--------|---------|
| `open` | Accepting counts. This is where imports, counts, sales and invoices land. |
| `finalised` | Reviewed, variance frozen — but still the **current** period, so re-runnable. |
| `rolledover` | Closed **and** succeeded by a newer period. **Locked history.** |
| `reopened` | A `rolledover` period temporarily unlocked for amendment (r62). |

`isClosedSession(s)` ⇒ `finalised || rolledover`. **`reopened` deliberately sits OUTSIDE it** —
that single fact is what re-enables the invoice guards and the live-variance branch for the
reopened period, while every other closed period stays locked.

### Active vs viewed period (r60)
- **`currentSession(c)` — the ACTIVE period. All WRITES go here.** Deterministic pick:
  the `open` session → else the highest-seq non-`rolledover` → else the highest-seq.
  (This replaced an old "last array element" heuristic; do not reintroduce it.)
- **`viewedSession(c)` — the period the DISPLAY is showing. Reads only.** Resolves
  `viewedPeriodId`, falling back to `currentSession()` when unpinned or when the pinned id no
  longer resolves. **Nothing in a write path may read `viewedPeriodId`.**
- The top-bar period dropdown pins `viewedPeriodId`; rollover and client-switch reset it to
  `null`. The selector only appears once closed (or reopened) history exists.

### Per-period data isolation
`computeVariances(client, session = null)` takes an **explicit session**; unspecified means
`currentSession()`.
- **LIVE** (`open` / `reopened`) → merges the period's **scoped** deliveries.
- **CLOSED** (`finalised` / `rolledover`) → reads **only** its frozen `sess.purchases`
  snapshot, so a later invoice edit can never retroactively move locked history.

`freezeSessionSnapshot(c, sess)` writes that snapshot: overall variance %, the deep-cloned
resolved `purchases`, and `varRows`. It **must be called while the session still computes
live** (status still `open`/`reopened`), then the status flips — mirror this ordering in any
new close path.

### Rollover chain
`rolloverPeriod()` (the older docs call this `finalisePeriodAndRollover()` — that name has
never existed in the code):
1. Requires a `finalised` current period, and **no** period left in `reopened` state.
2. `cur.status = 'rolledover'`.
3. Creates the new `open` period with `opening = JSON.parse(JSON.stringify(cur.closing))` —
   a **deep** copy, never shared count entries. Sets `newSess.prevId = cur.id` and
   `cur.nextId = newSess.id` so the chain walks both ways.
4. Resets `viewedPeriodId = null`, clears staged counts, lands on Stocktake.

### Period-scoped deliveries (r59)
`c.deliveries` is a **flat global list**. New deliveries are stamped `d.periodId` at three
creation sites. `resolveDeliveryPeriod(c, d)` attributes any delivery deterministically:
1. explicit `d.periodId` naming a real session;
2. **ref-match** — the session whose `purchases[*].invoiceRef` equals `d.r` (most reliable,
   survives rollover);
3. **date** — the latest period opened on/before the invoice date (`parseFlexDate` only
   resolves when a **year** is present);
4. otherwise the **earliest** period — never the current one.

`currentDeliveries(c)` is **dead** (zero call sites). `deliveriesForSession(c, sess)` is the
live one, used by variance, purchase KPIs and the grouped history table.

### Closed-period immutability (r61)
Invoice delete/edit is **blocked** for locked periods; purge and delete touch open sessions
only. One invoice reference (`invRef`) is stamped on both the delivery `r` and the session's
`invoiceRef` so a "ghost purchase" can't survive a delete. `deleteInvoice()` now
`dbSaveSession()`s. To change anything in locked history you must **reopen**.

### Reopen — a contiguous block, oldest-first re-close (r62 / r64)
- `eligibleReopenSession(c)` returns the ONE session reopenable next, walking a **contiguous
  block backwards** from the newest closed period, unlimited depth: nothing reopened → the
  highest-seq `rolledover`; otherwise → the immediate predecessor of the **oldest** reopened.
  Driven by `seq`; `prevId` is a defensive cross-check only (legacy chains may lack it).
- A reopened period is **never** the active period, so new counts/imports/sales are unaffected.
- **Re-close is enforced oldest-first** — gated on three UI surfaces with waiting messages.
- Reopen/re-close live on the **Finalise page** (r63), driven by `viewedSession`.

### Forward cascade on re-close (r65)
`recloseReopenedPeriod()` re-freezes the oldest reopened period, flips it to `rolledover`,
stamps `reclosedAt`, then cascades **exactly one hop**: the successor (`nextId` → seq fallback)
**inherits the corrected closing as its `opening`**, and is re-frozen only if
`isClosedSession(succ)`. It **never touches `succ.closing`** — that is a real physical count.
Deeper periods update as the user unwinds the block oldest-first.

### Amend a closing count (r66 — lifecycle complete)
`openAmendClosing(productName)` — a ✏️ on the variance row — edits one product's closing figure
on a `reopened` period. This is what turns the r65 cascade from a no-op into real forward
propagation.
- **Plain `{qty, unit}` entries ONLY.** Weighed entries (`weights[]` / `netWeightG` /
  `method:'weight'`) are **refused** so their per-vessel trail can't be destroyed by an
  ambiguous back-solve. Weighed amendment is deferred.
- A missing entry is created with a **base unit, never `'Cases'`** (or `countToUnits` would
  multiply by `caseSize` a second time).
- Every edit appends to `sess.amendments` (`{ product, oldUnits, newUnits, oldEntry, newEntry, ts }`).
- Status is re-checked at write time.

### Where a WRITE may land (r80)
`currentSession(c)` falls back to a **finalised** period so the DISPLAY has something to show. For
a WRITE that is silent data loss: a closed period computes from its frozen snapshot, so the write
never reaches variance, and r61 then refuses to let it be removed.

- **Every import/adjustment path targets `importTargetSession(c)`** → `{ session, reason }`:

### Pack size — CONFIRMED, never decided (r84–r87)
Two live corruptions came from a guessed 12 (LINDAUER BRUT 200ml was a 4-pack; a reviewed invoice
line a 6-pack).

- **`validPackSize(raw)` is the ONE rule** — whole, > 0, ≤ 500 → the number, else **null** (never
  `''`/`NaN`). Byte-identical twins in `index.html` and `mobile.html`.
- **`resolvePackSize(stamped, catalogue, nameForParse)` → `{ cs, unknown }`** is the ONE
  precedence everywhere a case expands: **stamped on the line/entry → catalogue `caseSize` →
  parsed from the name → ×1 with `unknown: true`**. A malformed stored value falls THROUGH, never
  coerced (`parseInt('12.5')` is 12). **No `|| 12` remains** (r87): ×1 under-states visibly; 12
  over-stated silently. **Never infer `unknown` from `cs === 1`** — a pack of 1 is legal.
- `countToUnits(entry, prod, packOut)` — pass `{}` to get `.unknown`. An unexpanded case supplies
  QUANTITY but never a per-unit COST. The flag renders as amber `📦 ?` (cell, popover) and
  `Pack ?` (PDF); `PACK_UNKNOWN_TITLE` is the one wording.
- **Every path that can SELECT `Cases` confirms the size first:** the desktop count row's Pack cell
  (`readCountRow` reports `caseSize` only for a `Cases` row); `finaliseStocktake` **refuses** an
  unresolved `Cases` row and writes nothing; `saveProduct` refuses `soldAs:'Cases'` without a size;
  the review modal's size is **mandatory when the split box is ticked and visible**
  (`invRefuseUnconfirmedPack`); mobile **prompts** (`countUnitChanged` → `promptPackSize` →
  minimal-patch `savePackSize`) instead of disabling Cases — refusing on the guarded surface only
  pushes the work to an unguarded one.
- **`finaliseStocktake` expands `Cases` to base units and RELABELS the entry**, leaving provenance
  (`_caseSize` / `_caseQty` / `_caseMixed`) that **nothing computes from**.
- **Case barcodes:** `unionBarcodes()` / `productBarcodes()` flatten `caseBarcode` into the match
  set, so `barcodeMatchKind()` (both files) must test `caseBarcode` **explicitly and FIRST** or a
  carton books one unit.
- Money is invariant under pack size only where the size RESOLVES (`qty × cs` up, `cost ÷ cs`
  down). r87 does not rewrite history: September's frozen `purchases` still holds the old guessed
  12 for `CHURCH ROAD CHARDONNAY`.

## Cost pricing — bulk grid and completeness gate (r96 / r97)
- **The bulk grid (Products → `$ Bulk cost pricing`) writes exactly FOUR fields, in place:**
  `costPrice`, `costPriceExGST` (`price / 1.15`), `cost` (display mirror), `costHistory`. It
  **never** rebuilds a product or routes through `saveProduct` (which rebuilds the whole object
  from the modal DOM and erases anything unpopulated). No master write. One PATCH.
- `applyBulkCostPrice(prod, price)` is the ONE write, change-gated (a no-op appends no history),
  stamped `BULK_PRICE_SOURCE = 'bulk price edit'`.
- **A blank box is not $0.00** (`BP_BLANK_MEANS_TEXT`): blank → unchanged; **a typed 0 is
  REFUSED**; junk/negatives refused by name. The box is `type="text"` — a number input turns junk
  into `''`, which reads as "unchanged". One bad row refuses the whole batch. The draft map
  `_bpDraft` (keyed by NAME) is the authority, not the DOM.
- **`noCostPrice: true` is a SILENCER, not a value (r97)** — set only by a deliberate tick

  Clearing deletes the key.
- **Resolve counted stock through `countToUnits`, NEVER `entry.qty`** — weighed spirits are stored
  `{qty: 0, netWeightG: 798}`; a `qty > 0` test missed 18 of 32 unpriced counted products.
- **Finalise WARNS, never blocks** (`#fin-unpriced-warn`, in the FIRST of the two identical
  `#finaliseModal` divs — the second is dead). **Rollover SOFT-BLOCKS** with a second confirm and
  never refuses.
- **Known, deliberately unfixed:** `saveProduct`'s new-product branch logs a
  `{price: 0, source: 'manual'}` `costHistory` entry from a blank form; most live products carry one.

## Backend failure and backup (r98 / r99)
The project auto-paused (free tier, ~a week idle); its hostname went NXDOMAIN and the app rendered
exactly like an empty account.

- **`DB.getResult` / `upsertResult` / `deleteResult` → `{ ok, rows, reason, status, error }`**;
  `reason` is `'ok'` (answered, rows may be `[]`) · `'unreachable'` (fetch REJECTED — no HTTP at
  all) · `'http'` (non-2xx, status carried) · `'notready'`. `DB.get/upsert/delete` are back-compat
  wrappers. A failed or PARTIAL load makes `dbLoadAll` return false.
- **`fetch` only REJECTS on network errors — always check `r.ok`.** Pre-r98 `dbSaveClient` said
  "✓ Saved" on every HTTP rejection.
- **Failures are PERSISTENT, never a 1.8 s toast:** `renderDbDownBanner` (`#db-down-banner`);
  `dbDownText(what)` is the one wording; `reportWriteFailure(what, reason, status, detail)` is the
  ONE write-failure surface. Only `unreachable` flips `_dbDown` — an `http` failure means the
  server is alive. `refuseWriteBackendDown(what)` (TRUE = refused) guards 8 write entry points;
  reads stay usable. `_dbDown` is **never** inferred from `clients.length === 0`.
- **Mobile `loadProductsFromSupabase` is still silent on failure** (reported r98, not fixed).
- **Backup** (Finalise audit → `⬇ Download backup`, and automatically after every rollover): the
  four tables `dbLoadAll` reads, read FRESH through `DB.getResult` — only `'ok'` accepted, an empty
  table is clean, any failing table refuses the whole export. **BOTH session stores.** The rollover
  snapshot waits on the rollover's writes (`_rollSaves`), is detached and cannot undo it. No restore
  path (deliberate). Filename:
  `auditpro-backup_<venue>_<YYYY-MM-DD>[_rollover-<period>]_build-<APP_VERSION>.json`.

## Invoice PDF storage — through the Worker (r100)
- `uploadInvoicePDF(file, ref, slug)` POSTs the raw PDF to `INVOICE_UPLOAD_URL`
  (`/invoice-pdf?slug=&ref=`); the Worker upserts `Invoices/<slug>/<ref>.pdf` and returns a
  10-year signed link. Still returns URL or `null`. No key that bypasses RLS is in the browser.
- **The route is narrow, not trusted:** PDF only (content type + `%PDF-` bytes), 10 MB enforced on
  the bytes read, slug `[a-z0-9_]{1,64}`, ref `[A-Za-z0-9_-]{1,100}`; it builds and signs only its
  own path. **Headers to Supabase are built, never copied** — a forwarded browser User-Agent makes
  Supabase refuse the secret key (401).
- **`invoiceStorageRef(ref)` is the ONE storage-key rule** — exactly `attachInvoicePDF`'s old
  sanitisation. The raw AI-parsed ref once made `INV/26-27/0363` a nested folder.
- **Only PDFs are stored.** Both invoice inputs accept photos and the AI reads them; a photo is
  refused by name and no copy is kept.
- **An upload failure is NOT a database failure.** Own persistent banner (`#upload-fail-banner`),
  one wording (`invoiceUploadFailText`), never touches `_dbDown`/`_dbSaveFail` — r98's
  `reportWriteFailure` would say the invoice wasn't saved and refuse every DB write.
  **`retryInvoiceUploads()` is the ONLY recovery path:** re-importing an invoice skips the upload,
  and `attachInvoicePDF` has **no caller**. Retry re-resolves the invoice by slug + ref.
- Existing links are signed by Storage's own URL-signing key, not the API keys.

## Density Architecture
**`ap_master_products` is the single source of truth for product density.** Venue rows
(`ap_clients.data.products`) hold per-venue copies for counts/stock/prices, but their
**density is merged from master at load time** — the venue's own value is overwritten.

- **Load merge** — `dbLoadAll()` builds a `slug → density` map from `masterProducts` and
  overrides every matching venue product. Venue-specific fields (counts, stock, prices, par)
  are untouched. Logs `[AuditPro] Density merge — X products updated from master.`
  Mobile mirrors this in `loadProductsFromSupabase()`.
- **Density edits write to master** — `saveProduct()` and the "existing product" branch of
  `applyInvoiceToProducts()` both call `addToMasterCatalogue()`, so a correction can't drift back.
- **Invoice imports inherit density from master** before defaulting to 1.00 (both
  `renderInvoiceResults()` and the master-write loop in `applyInvoiceToProducts()`).
- **Slug consistency** — `getMasterProduct()` uses the same `masterSlug()` derivation
  (`name → lowercase → non-alphanumerics → '_'`) as the upsert key, so a rename can't create a
  duplicate master row.
- **Mobile has NO master-products writer** — it reads master density but never writes it.
- Beer & Cider = 1.014 (was 1.00). Wine = 0.9805 (was 1.00; repaired r19).
  **RTD is always counted as full units, so RTD density is irrelevant and stays 1.00.**

## Mobile Write Discipline
**Mobile writes to `ap_clients` MUST be minimal patches.** `pushProductToSupabase()` spreads
`{...cur, ...prod}`, finds the target by **NAME** (`n`/`name`), and only guards `costPrice`,
`density` and `soldAs`.
- If a product object reaches it **without `n`/`name`, it appends a duplicate** instead of
  updating.
- A full-object mobile save will erase desktop-only fields (this is how `caseSize`/`caseBarcode`
  got wiped before r73).
- For new mobile UI that needs a product picker, **reuse `searchProducts()`'s row renderer**
  rather than building a parallel list.

### Mobile add-product schema (r79)
`saveMobileProduct()` writes a **full object**, so every field it emits must be user-entered or
guarded in `pushProductToSupabase`. Blank-guard list: `costPrice, density, soldAs, caseSize,
costPriceExGST, par` (blank includes `[]`). `parunit` and `costHistory` are derived defaults that
**never** overwrite a stored value — a blank-guard can't protect an always-non-blank field. A
guessed `serveVol` (`serveVolGuessed`) never overwrites a measured one. Case size is the only extra
field worth capturing on the phone — no "more details" accordion. `needsInfoAlert()` is the review
surface and self-clears on `saveProduct()`.

### Mobile weigh bridge (r71 / r72)
The weigh UI is an **ID-bound singleton** (BLE writes to `#scale-reading`) — **ARM it, never
clone it**. `armWeigh(product, origin)` + `_weighOrigin` is the one bridge from a Search result
or a Scan result into the weigh panel. `setMethod()` only **hides** panels, so
`clearSearchArm()` / `clearScanArm()` exist to stop a duplicate-line footgun. The count-screen
input panel scrolls with sticky confirm buttons — **never set inline `position` on those
buttons**; numpads are inline-styled so overrides need `!important`; keep taps ≥44px.

## Invoice Matching Logic
Runs fresh inside `openInvoiceReviewModal()` every time the modal opens (never cached —
`_cleanName` in `_invoiceDataStore` is stale by design). r88: the matcher used to match
CONFIDENTLY to the wrong product, and $1,164.72 of kegs vanished.

**`invMatchLine(client, item, supplier)` is the ONE matcher** → `{ prod, kind, score, code }`:
1. **Supplier code** (`productCode`; `invCodeKey` is **not** `normalizeBarcode` — leading zeros
   matter; `supplierCodeFrom` scopes a learned code to its supplier)
2. Barcode (exact, strips leading zeros)
3. Exact name (case-insensitive)
4. Normalised name (strips volumes, pack sizes, BTL/KEG/CAN, apostrophes)
5. Partial string includes
6. Word-overlap score (best score; a tie goes to array order). **Do not touch** without its own
   dual-build gate — the live merge re-runs it on every render.

Normalisation strips: `'`, pack sizes (24S), BTL/BTLS, CAN/CANS, KEG/KEGS, CASE/CASES, CAR,
RTD, volumes (330ml, 50L).

- **Venue catalogue ONLY.** Master is enrichment (density/vessel), never the answer; a master-only
  match is UNMATCHED, because `computeVariances` silently drops purchase keys not in
  `client.products`.
- `INV_CONFIDENT_KINDS = ['code','barcode','exact']` → green, collapsed; anything else → **amber,
  expanded**, naming how it matched.
- **A code is learned from a DECISION, never a guess** (a confident match or a human binding); a
  blank never overwrites, a different stored code is kept and reported.
- **The name field must be BOUND:** `invNameBinding(id, i)` → `'catalogue'` | `'new'` (ticked
  "Create as a new product") | `''` (blocks) | `null` (no input). Never validate on non-emptiness.
- **ONE resolved name:** `invResolvedLineName(id, i, item)` (modal input, else
  `_cleanName || item.name`). The live merge discards a `_cleanName` that names no venue product.
- **Quick import means "everything is already matched"** — `invRefuseUnmatchedLines` (TRUE =
  refused) also covers the dump path. Orphan purchase keys show on Variance
  (`renderVarOrphanBanner`); an invoice REF alone never decides an orphan is lost.

Unmatched items → blank red-bordered field; Confirm stays disabled until every row is bound.

**Invoice totals & extras:** the invoice total is `d.t` — the total **printed on the invoice,
incl. GST** — which can exceed the sum of line items. The gap (fuel surcharge, freight, levies)
is stored as `d.extras = d.t − lineSum`, and `saveEditedInvoice()` preserves it through line
edits. A "wrong invoice total" is almost always a wrong **stored `d.t`** (a write-path/data
problem) — query live Supabase before editing any read logic.

**Review-modal render:** "the fields don't update" means the row template **threw mid-render**
(unguarded `.toFixed` / `.match` on an undefined row field), so the inputs never rendered.

## Variance Calculation
`computeVariances(client, session = null)` — runs even without a finalised session.

**Purchase sources:** for a LIVE period, `deliveriesForSession()` (period-scoped, fuzzy name
matching) merged with `session.purchases`; for a CLOSED period, the frozen `session.purchases`

**Only products in `prodMap`** (the catalogue) are shown — prevents test/stale rows appearing.

**Unit display:** Bottles/Cans/RTD show units ("36 units"); Spirits/Wine/Kegs show volume
(L/ml). `fmtVol` is **neutral**; the signed totals formatter is `fmtVolSigned` — don't mix them.
`unitLabel` / `isPouredProduct` operate directly on variance rows.

**Sales depletion:** recipe-aware via `buildSalesDepletion()` when the session carries per-line

**`downloadVariancePDF()`** works from any page — the hidden `.page` divs plus `renderVarTable()`

### Signed purchases, % floors and stock adjustments (r81–r83)
- **A negative purchase quantity is stock going OUT.** Display gates are `!== 0`, never `> 0`.
  **`countToUnits`' `qty > 0` clamp STAYS** (a count can't be negative), so an adjustment must
  NEVER be modelled as a count entry — it would be clamped to 0 and vanish.
- **Per-product % floor:** `VAR_PCT_MIN_EXPECTED = 1` unit; `varPctDisplay(expected, actual,
  costImpact)` is the ONE decision point — `'—'` below the floor, coloured by cost impact.
  `varPctNum` stays a number; `varPctValid` says whether it is real.
- **Stock adjustments** (Purchases → `⇄ Stock adjustment`) are deliveries with `kind:'adjustment'`,
  `reason`, `note`, `direction:-1|1`, `mirrorOf:null`, `r:'ADJ-'+Date.now()+'-'+random`, and
  `periodId` = the OPEN session. Direction is a toggle, never a typed minus. Lines carry
  `_cleanName` and `_incGST` (the fields the merge reads), already expanded to base units, and
  ALSO write `session.purchases` via the r77 `byRef` ledger.
- **The picker is HARD-BOUND (r83):** a row binds only by clicking a result —
  `saPickProduct(rowSeq, catalogueIdx)` carries an INDEX, never a name in an `onclick`. Typed text
  is never savable. Cost and pack size re-derive on every pick.
- **Adjustments never reprice the catalogue:** the write-back licence is
  `!_adjustment || _costFromSupplier`.
- `saveEditedInvoice` carries each line's `unit` / `caseSize` through and rewrites this invoice's
  `byRef` slice. Report Purchase History is period-scoped (`deliveriesForSession`).

## Report and variance invariants (r92–r95)
- **A READ must not reprice the catalogue (r92).** `computeVariances` WRITES
  `client.products[idx].costPrice` from the period's purchase cost — gated on provenance
  (`costIsSupplier`) **and** `isActivePeriod`: identity (or id) against `currentSession(client)`,
  **never** `session == null`, so passing the current period explicitly still writes and every
  past or reopened period does not. It is the ONLY mutation on the read path.
- **An aggregate % needs a denominator (r93).** `aggVarPct(expectedVal, varianceVal)` →
  `{ valid, pct, reason }` needs `expectedVal >= AGG_PCT_MIN_EXPECTED_VAL` ($1) and
  `|pct| <= AGG_PCT_MAX_ABS` (100%, **inclusive** — counting nothing is exactly −100% and must
  print). `variancePct` stays a number; `varPctValid` / `varPctReason` say whether it is real.
- **Three category states:** (a) genuine zero → green; (b) % suppressed, dollars real → amber;
  (c) **no cost data** (`pricedCount === 0`) → grey **"Not assessed"**, never green. Detect (c) on
  the CAUSE, never the symptom (all dollars zero). `ragClass` maps unknown values to red — handle
  any new state explicitly. The AI context is told never to call (c) clean.
- **The trend plots a GAP, never a 0.** A stored `overallVariancePct` of exactly 0 is ambiguous and
  falls through to the recompute; `freezeSessionSnapshot` stores null.
- **The report describes the period it is titled with (r94):** `calculateReportData` resolves
  `_reportSession = session || currentSession(client)` ONCE for variance, `periodDays`, `prevSess`,
  purchase history and the trend anchor (`data.sessionId`, by ID). A fix can break a reader that
  was correct *because of* the bug — the anchor had to land in the same commit.
- **`prevSessionOf(c, sess)`** — `prevId`, else the seq-ordered predecessor by scanning. **Never
  `indexOf`, array position or `===`** on sessions: the array is rebuilt and re-sorted on reload.
- **The report selector is keyed by session ID (r95):** `resolveReportSession(c, id)` →
  `{ session, reason: 'ok'|'fallback'|'none' }` (a fallback is announced); `meta.sessionId` reaches
  `saveReportRecord`. Seeded from `viewedSession` at tab-open only; `fullRptSessionChanged` must
  **never** touch `viewedPeriodId`.
- `totals.purchaseVal` (ex-GST, catalogue cost) and Purchase History's `d.t` sum (incl. GST +
  freight) **differ by design**.

## Common Pitfalls

1. **`p.n` crashes if undefined** — always `p.n||p.name||''`.
2. **`indexOf` returns −1 after a Supabase reload** — use `findIndex` by name.
3. **`forEach` with async doesn't await** — use `for...of` with `await` for sequential saves.
4. **Supabase PATCH returns 204 even when RLS blocks the write** — verify with a GET.
5. **`on_conflict=slug` is required** for upserts — without it POST 409s.
6. **GitHub Pages caches aggressively** — check `APP_VERSION`; force a redeploy with a trivial
   commit; keep `.nojekyll`.
7. **`_cleanName` is cached in `_invoiceDataStore`** — `openInvoiceReviewModal()` re-matches fresh.
8. **Writes must use `currentSession()`, reads may use `viewedSession()`** — never the reverse.
9. **Never write to a closed period** — reopen it, amend, re-close (oldest-first).
10. **A `'Cases'` entry with no confirmed pack size now expands ×1 and raises a flag** (r87)
    — it no longer silently 12×'s. Still store base units, never `'Cases'`, when synthesising an
    entry: ×1 UNDER-states, which is visible and recoverable, but it is not correct. Every path
    that can SELECT `Cases` must confirm the pack size first (r84 desktop count row, r85
    everywhere else); `validPackSize` is the one rule and it returns **null**, never a fallback.
    **Never infer "unknown" from `cs === 1`** — a confirmed pack size of 1 is legal.
11. **Mobile product pushes must be minimal patches keyed by name**, or they duplicate rows and
    erase desktop-only fields.
12. **A match is not a match until it names a VENUE product** (r88). The master catalogue is
    enrichment only — never the answer — and `computeVariances` builds rows only for names in
    `client.products`, so a master-named purchase key is money that vanishes without a message.
    `_cleanName` must BE a catalogue name; when it is not, the live merge discards it and
    re-matches. Never validate the review modal's name field on non-emptiness alone.
13. **A backup must capture BOTH session stores** (r99). `ap_audit_sessions` **overwrites**
    `ap_clients.data.auditSessions` at load, so one copy alone cannot reproduce the venue — the
    same reason r80's live `openDate` fix had to be applied twice. And an export must read the
    server, never memory: a half-loaded state (r98) looks complete once serialised.
14. **`clients = []` at boot** — there is no hardcoded demo data; everything loads from Supabase.

### Test-harness patterns that have worked
- **Extract-fn-and-diff-vs-HEAD** — pull a single function out of both revisions and diff, to
  prove a change is scoped. The extractor needs a **mode-stack scanner** to survive nested
  template literals and quoted regexes.
- **node `vm` sandbox + DOM stub** — run the real script against a stub DOM. Top-level
  `let`/`const` are **lexical**, so `sandbox.X = …` silently no-ops; drive all state through
  `runInContext`.
- The r66 lifecycle work shipped with a 46-check end-to-end harness calling the **real**
  `computeVariances`.

## Saturday Audit Workflow
1. Mobile → connect to the venue → count all stock → **Accept & sync** (note the code)
2. Desktop → **Import by code** → rows stage into the open period
3. Invoices arrive → upload PDFs → review & match → import
4. End of week → upload the POS sales CSV
5. Variance page updates automatically
6. **Finalise & run variance** → freezes the snapshot (`finalised`)
7. **Close & roll over** → locks the period (`rolledover`) and opens the next with opening
   stock carried over
8. A **backup snapshot downloads automatically** on rollover (r99). Keep it — the three live
   periods only ever existed on the server. Take one any time from Finalise audit →
   **Download backup**.

**To correct locked history:** Finalise page → **Reopen** (newest closed first, contiguous
block) → edit invoices / amend closing counts → **Re-close oldest-first** (cascades the
corrected closing into the successor's opening).
